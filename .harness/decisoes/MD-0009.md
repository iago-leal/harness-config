# MD-0009 — actions do CI pinadas em versão exata (Node 20 → 24)

- **D:** Subir as três GitHub Actions do `ci.yml` para as versões atuais e pinar cada uma em **tag exata**, não em major movível: `actions/checkout@v4 → @v7.0.0`, `astral-sh/setup-uv@v5 → @v8.2.0`, `actions/setup-python@v5 → @v6.3.0`.
- **PORQUÊ:** O GitHub aposentou o Node 20 dos runners; as versões antigas declaravam `node20` no seu `action.yml` e estavam sendo forçadas a rodar no Node 24, emitindo um aviso em todo run — benigno hoje, falha certa quando o "forçar" terminar. As versões latest já usam `node24`. O pin em versão **exata** (em vez da major tag movível usada antes) atende à reprodutibilidade temporal (Princípio 5.3): uma tag `@v7` é repontável pelo mantenedor da action e mudaria o CI sem aviso, ao passo que `@v7.0.0` dá build determinístico, atualizado conscientemente nos rituais de manutenção (5.7). A escolha também resolve uma assimetria concreta: `astral-sh/setup-uv` **não mantém major tag movível** (`@v8` não existe; suas tags movíveis são por minor, como `v7.6`), então pin exato é o único critério uniforme entre as três.
- **DESCARTADO:** (1) Major tag movível (`checkout@v7`, `setup-python@v6`) — inviável de forma uniforme (sem `setup-uv@v8`) e não-determinística, contra 5.3. (2) Pin por SHA — proteção máxima de cadeia de suprimentos, mas custo de manutenção maior (atualizar hash à mão); reavaliar se o projeto evoluir para a categoria Produto. (3) Versão mínima que resolve o Node 20 (`checkout@v5`) em vez da latest — preterido: ficar na latest mantida reduz a defasagem do próximo ciclo.
- **ESTADO:** Editado e travado pelo mantenedor (24/06/2026). Requereu reconceder o escopo `workflow` ao token `gh` (antes só `gist, read:org, repo`) para que o push tocasse `.github/workflows/`. CI deve seguir verde e sem o aviso de Node 20. Recuperável por git.
