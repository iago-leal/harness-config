# MD-0015 — Gate de registro de microdecisões: fingerprint no estado e soft-block único no Stop

- **D:** O encerramento ganha um 3º portão (`DECISAO_PENDENTE`, família do COMMIT/NARRATIVA_PENDENTE): trabalho substantivo desde a âncora (qualquer arquivo versionável — repositórios documentais contam) sem ficha `MD-*.md` nova bloqueia o `encerrar-sessao` até registrar ou declarar `--sem-decisao` (rastro na narrativa). No `Stop` do Claude, `harness decisions --gate` emite `{"decision":"block","reason":...}` **uma única vez por estado de pendência**. O anti-loop persiste como dois fingerprints (`sha1(âncora+HEAD+sujos)`) em campos opcionais do front-matter do estado de sessão, zerados no fechamento. No Antigravity, o mesmo veredito é só aviso em stderr (`{}` intocado). Flag `decisions.require_registration`, default ligado; avaliação pura em `core/decisions/gate.py`; `GitPort.list_changed_paths_since` novo.
- **PORQUÊ:** (1) O canal do `Stop` que alcança o modelo é apenas o bloqueio com `reason` — stdout exit 0 não é reinjetado; o "lembrete não-bloqueante" pedido só existe como soft-block limitado por fingerprint (RF-08 reconciliado na spec). (2) O fingerprint vive no estado de sessão porque é a exceção consagrada do pré-check de pendência (RN-N34): um scratch novo sob `.harness/` viraria `COMMIT_PENDENTE` perpétuo ou exigiria entrada de `.gitignore` em toda a base (lição do T7). (3) O diff da âncora é indispensável: o pré-check da 019 força commit antes do fechamento, então `list_dirty_paths` sozinho é cego ao trabalho da sessão.
- **DESCARTADO:** (a) Scratch `.harness/decision-gate.json` para o anti-loop — vira pendência de commit ou nova entrada de gitignore na base instalada. (b) Lembrete via `systemMessage`/stdout puro no Stop — não alcança o modelo, só o usuário. (c) Detecção semântica ("o diff parece decisão?") ou parse do transcript — não-determinístico, viola o princípio de sinal físico. (d) Filtrar o sinal a código-fonte — o mantenedor tem repositórios de contratos/documentos cujas alterações são exatamente as decisões a registrar. (e) Bloquear também o Stop do Antigravity — RN-N26 proíbe; advisory. (f) Exit 2 no soft-block — ambíguo com falha real; o bloqueio é só pelo JSON, exit 0 sempre.
- **ESTADO:** Decidido e implementado (15/07/2026, feature 022). Suíte 293 passed (36 testes novos); smoke real A–F (bloqueio, ficha libera, escape com rastro, anti-loop, JSON único no `--gate`, advisory `{}`). Core 2.0.1 → 2.1.0; skill `encerrar-sessao` 1.3.0; settings/snippet deste repo regenerados. Gemini fora desta iteração (decisão de escopo do clarify). Propagação aos projetos-alvo no próximo `upgrade`/`migrate`; o core-raiz de `~/dev` converge via `.harness/upgrade-raiz.sh`.
