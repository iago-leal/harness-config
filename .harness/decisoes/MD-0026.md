# MD-0026 — Borda MCP de encerramento deriva as visões e as versiona no commit de fechamento

- **D:** A semântica de derivação da borda de encerramento saiu do `SessionCloseFlow._derive_decision_views` para o `DecisionService.derive_views_for_close(config, err) -> list[str]` (fonte única), e a tool MCP `session_command("encerrar-sessao")` passou a chamá-la antes do `execute_command`, incluindo as visões regravadas no commit de encerramento via o parâmetro novo `caminhos_extras` do `CommandService.execute_command` (stage sempre por caminho explícito, jamais `git add -A`). Avisos não-bloqueantes voltam anexados à resposta da tool, já que o MCP não tem stderr útil. Sessão ausente segue no-op sem derivação (D1 da 016). Core 2.6.3 → 2.6.4.
- **PORQUÊ:** RN-N56 exige que toda borda de encerramento derive as duas visões na mesma passada; o MCP era a única que fechava sem derivar. Diferente do fluxo interativo, essa borda não tem portões que forcem o commit das visões antes do fechamento: sem incluí-las no commit de encerramento, a árvore terminaria suja num repositório recém-fechado, exatamente o que a MD-0025 descartou.
- **DESCARTADO:** (a) Rotear o MCP pelo `SessionCloseFlow` — acrescentaria os três portões a uma borda sem interlocutor (assimetria deliberada da 024/D-04), mudança de comportamento muito maior que a dívida. (b) Derivar e deixar as visões sujas no working tree — repete o descarte (a) da MD-0025. (c) Segundo commit só para as visões — dois commits por fechamento poluem o histórico sem ganho. (d) Duplicar a semântica no servidor MCP — divergiria do flow na primeira manutenção; a extração para o service elimina a segunda cópia.
- **ESTADO:** Implementado (11/08/2026, TDD direto; 7 testes novos em `test_decisions.py`, `test_commands.py` e `test_mcp.py`; suíte 404 verdes; core 2.6.4).
