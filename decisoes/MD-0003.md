# MD-0003 — Reinjeção para os três harnesses e mecanismos por harness

- **D:** A feature 004 entrega a reinjeção de estado para os TRÊS harnesses — Claude, Gemini CLI e Antigravity (`agy`) — não só o Claude. O `cmd resume`/`cmd encerrar-sessao` produzem o texto puro da narrativa; uma Strategy de saída por-harness, selecionada pelo `active_harness` do `harness.toml` e reusando o padrão de `core/install/harness_profiles.py`, aplica o mecanismo de cada um na borda. Duas famílias confirmadas: (i) **hook `SessionStart` + `hookSpecificOutput.additionalContext`** — comum a Claude e Gemini CLI (formato idêntico; gatilho nos respectivos `settings.json`); (ii) **projeção em arquivo estático relido a cada boot** (`.agents/rules/estado-sessao.md` ou bloco no `AGENTS.md`) — Antigravity, que não expõe hook de injeção de contexto. A fonte canônica `.harness/estado-da-sessao.md` permanece única; a projeção do Antigravity é derivada dela.
- **PORQUÊ:** O mantenedor usa os três harnesses (perfis em `harness_profiles.py`; o BASTÃO global circula entre Claude e antigravity). Cobrir os três agora dá paridade de retomada e evita retrabalho. A investigação web (23/06/2026) confirmou que Claude e Gemini compartilham o mesmo envelope `additionalContext`, tornando o Gemini um incremento barato sobre o Claude; o único ramo distinto é o Antigravity. A Strategy, antes descartada por YAGNI (um só consumidor), passa a se justificar: há três consumidores reais.
- **DESCARTADO:** (1) Só Claude, Gemini/Antigravity como follow-up — recusado pelo mantenedor; paridade imediata preferida. (2) Um mecanismo único para os três — impossível: o Antigravity não expõe hook que injete stdout no contexto (os hooks dele decidem allow/deny/ask de tool calls); forçar caminho único quebraria. (3) Antigravity via MCP resource servindo o estado — mais "vivo", mas exige o agente decidir chamar (não é injeção garantida no boot) e adiciona servidor a manter; preterido pela projeção em arquivo estático, mais simples e versionável. (4) Wrapper shell com jq para o Gemini (como no exemplo da doc) — desnecessário se o próprio `cmd resume` já emitir o JSON `hookSpecificOutput`, que serve Claude e Gemini igualmente.
- **ESTADO:** Decidido e travado (23/06/2026). Mecanismos confirmados por investigação web com fontes: Claude — doc oficial de hooks do Claude Code; Gemini CLI — hooks `SessionStart`, exige ≥ 0.25 (hooks desde a 0.24, regressão #16697 já corrigida, estável v0.45); Antigravity (`agy`, binário Go; config em `.agents/`) — sem hook de injeção, contexto por markdown estático relido a cada sessão. Pendência técnica para o `/reversa-plan`: como atualizar âncora/status no boot do Antigravity — reinjeção passiva (estado materializado no `cmd encerrar-sessao`, relido no próximo boot) versus hook `PreInvocation` do `agy` rodando `cmd resume`. Pré-requisito Gemini ≥ 0.25 a checar no ambiente.
