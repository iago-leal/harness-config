# MD-0012 — `encerrar-sessao` resolve o core do upstream quando não há core local (fonte única)

- **D:** O `_bootstrap.py` da skill `encerrar-sessao` (asset da feature 018) passa a resolver o Harness Core na **mesma ordem do shim `./harness`**: primeiro o core vendorizado em `.harness/harness-core`; na ausência, o core do `upstream_path` registrado no `harness.toml`. `resolve_core` ganhou dois helpers puros — `_core_at(base)` (core sob um caminho se expõe `src/main.py`) e `_read_upstream_path(root)` (lê o campo do `harness.toml` por regex de linha, o mesmo contrato do `sed` do shim, sem depender de biblioteca toml antes do re-exec). `bootstrap_core` não mudou: o re-exec sob a venv e o `sys.path` já usam o `core` devolvido — agora o do upstream. Bump da skill 1.1.0 → 1.2.0.
- **PORQUÊ:** A feature 020 (fonte única) parou de copiar o `harness-core` e a venv para o projeto-alvo — o shim executa o core do upstream. Mas o `_bootstrap.py`, anterior ao shim, exigia `.harness/harness-core/src/main.py` **local**, que num projeto migrado nunca existe. Resultado: a skill estourava `CoreNotFoundError` e o único desvio era `./harness cmd encerrar-sessao` — a skill, que é o ponto de entrada documentado, ficava inservível em toda instalação migrada. Espelhar a resolução do shim fecha essa lacuna com a fonte única e mantém o `resolve_core` puro e testável (ponto único de teste do bootstrap).
- **DESCARTADO:** (1) Fazer a skill delegar ao wrapper `./harness cmd encerrar-sessao` — jogaria fora o entry Python testado da 018 e reacoplaria a skill ao shim shell. (2) Usar `tomllib`/pydantic para ler o `upstream_path` — indisponível/não instalado sob o python do sistema **antes** do re-exec na venv; a regex de linha replica o contrato do shim sem dependência. (3) `expanduser` no `upstream_path` — o `init` grava sempre `abspath`, então seria no-op; manter a leitura crua preserva a paridade byte-a-byte com o `sed` do shim (invariante importante: os dois resolvedores do core precisam concordar). (4) Tratar como feature forward completa — é correção cirúrgica (~40 LOC + testes), cabe no registro leve TDD-direto.
- **ESTADO:** Decidido e travado (05/07/2026). TDD: 4 testes novos em `test_skill_scripts.py` (fallback ao upstream, precedência local > upstream, `upstream_path` presente mas core ausente → erro barulhento, leitor do campo). Propagação aos projetos já migrados fica para o `harness migrate`/`init` (a skill materializada neles ainda carrega o `_bootstrap.py` antigo).
