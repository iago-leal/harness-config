# MD-0007 — bootstrap recusa-se a instalar fora de um repositório git e oferece `git init`

- **D:** Endurecer o comando `bootstrap`. No domínio, `BootstrapService.install_hooks` passa a recusar a operação com `NotAGitRepositoryError` quando o caminho não é um repositório git (`.git` ausente), em vez de criar cegamente `.git/hooks`. Na apresentação, a CLI detecta a ausência e **oferece** inicializar o repositório com `git init`; aceita o usuário, roda a inicialização (novo método `GitPort.init_repo`) e instala os hooks; recusa ou está em contexto não-interativo (sem TTY), aborta com erro barulhento e `exit 1`, sem instalar nada.
- **PORQUÊ:** O gerador instalava os hooks em `os.getcwd()/.git/hooks` sem verificar a existência do `.git`, e `fs.makedirs` materializava o caminho do nada. Rodar `bootstrap` fora da raiz — por exemplo, com o cwd dentro de `harness-core/` — criava um `.git` degenerado (só `hooks/`, sem HEAD, refs ou objects), exatamente o acidente observado e limpo na sessão anterior (ver MD-0006). Um hook só faz sentido dentro de um repositório git real; instalá-lo sem ele é estado inválido e silencioso — o oposto da falha explícita que o projeto persegue. A detecção fica no domínio, via `fs.exists(.git)`, espelhando a validação que o `InitializationService` já fazia no destino do `init`; a interação (prompt) fica na camada de apresentação, preservando a pureza do serviço e sua testabilidade.
- **DESCARTADO:** (1) Inicializar o `.git` sem perguntar — recusado: transformar um diretório arbitrário em repositório git é decisão do usuário, não efeito colateral de um instalador de hooks. (2) Expor uma flag `--init-git` em vez do prompt — preterido em favor da oferta interativa solicitada, com recuo determinístico (sem TTY, não pergunta e aborta) para não travar `init`/`upgrade`, que chamam o `bootstrap` por subprocess — embora nesses fluxos o `.git` já exista e o ramo de oferta nunca seja alcançado. (3) Detectar o repositório via `git rev-parse --is-inside-work-tree` — preterido por `fs.exists(.git)`, que não paga o custo de um processo, é consistente com o `init_service` e aceita tanto o `.git` diretório quanto o arquivo de worktree.
- **ESTADO:** Implementado, provado de ponta a ponta (sem git → recusa e `exit 1`, sem criar `.git`; com git → instala os dois hooks) e travado pelo mantenedor (24/06/2026), fora do pipeline forward (TDD direto). Suíte verde (117 passed). Recuperável por git.
