# MD-0011 — Slash command de encerrar-sessao resolve a raiz via git (robusto a cwd)

- **D:** O corpo dos slash commands de `encerrar-sessao` passa a fazer `cd` para a raiz do projeto **antes** de invocar o wrapper. No Claude: `` !`cd "$(git rev-parse --show-toplevel)" && ./harness cmd encerrar-sessao` ``, com `allowed-tools` ampliado para `Bash(cd:*), Bash(git rev-parse:*), Bash(./harness cmd encerrar-sessao:*)`. No Antigravity: `cd <ABS> && <ABS>/harness cmd encerrar-sessao` (o `<ABS>` já era resolvido na materialização). Substitui o `./harness` relativo puro do Claude, que assumia cwd na raiz.
- **PORQUÊ:** O `!`-bash de slash command do Claude **não** roda garantidamente na raiz do projeto — roda no cwd da sessão, que pode ser um subdiretório. Aí `./harness` (relativo) falha com `no such file or directory: ./harness` (reproduzido em `~/dev/TECH+` rodando de um subdiretório). E há um segundo defeito latente: mesmo achando o wrapper por caminho absoluto, o `main.py` resolve `harness.toml` e `estado-da-sessao.md` **relativos ao cwd**, lendo config/estado errados de um subdiretório (o `handoff` mostrou `Feature: N/A` em vez da feature real). O `cd "$(git rev-parse --show-toplevel)"` resolve os **dois** eixos de uma vez e sobrevive a repo movido (o git devolve o caminho atual), diferente de embutir caminho absoluto fixo.
- **DESCARTADO:** (1) Manter `./harness` relativo — a premissa "o `!`-bash roda na raiz" é falsa; quebra fora dela. (2) Caminho absoluto fixo no Claude (como o Antigravity) — acharia o wrapper, mas o repo movido quebraria sem `upgrade` e, sozinho, não corrige o cwd do `main.py`. (3) `cd "$SCRIPT_DIR"` **dentro do wrapper** — corrigiria o cwd para toda invocação, mas quebraria comandos que recebem **caminho relativo** como argumento (ex.: `format <arquivo>` relativo ao cwd do chamador); efeito colateral inaceitável. Por isso o `cd` vive no slash command (que não passa caminhos relativos), não no wrapper. (4) `${CLAUDE_PROJECT_DIR}` — não expande no `!`-bash (issue #33815), viraria `/harness`.
- **ESTADO:** Decidido e travado (26/06/2026). Bump 1.2.50 → 1.2.51 (gate da rematerialização não-stale). Verificado: suíte 180 passed; `~/dev/TECH+` atualizado por `./harness upgrade` e o comando validado de um subdiretório aninhado (resolve a raiz e lê o estado real, enquanto a forma antiga ainda falha com `no such file or directory`). O Antigravity herda o mesmo `cd` por consistência, embora seu caminho absoluto já achasse o wrapper.
